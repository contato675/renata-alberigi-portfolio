# 08 · Descoberta por IA e i18n EN/PT-BR

## URLs relativas à base do site
| Recurso | Inglês | Português |
|---|---|---|
| Página inicial | `/` | `/pt-br/` |
| Markdown inicial | `/index.md` | `/pt-br/index.md` |
| Projeto | `/works/<id>/` | `/pt-br/works/<id>/` |
| Markdown do projeto | `/works/<id>/index.md` | `/pt-br/works/<id>/index.md` |
| Dados estruturados públicos | `/portfolio.json` | `/pt-br/portfolio.json` |

No Pages todos recebem o prefixo `/renata-alberigi-portfolio`. `llms.txt`, `llms-full.txt`, `robots.txt`, `sitemap.xml` e404 são gerados na base. IDs/títulos/fotos só existem quando houver cadastro real publicado, não como URLs fictícias.

## Conteúdo, não apenas arquivos
Agentes recebem HTML pronto, biografia textual, fichas completas, links convencionais, imagens com alt/dimensões e transcrição de vídeo. O carrossel não esconde conteúdo de quem não executa JS. Markdown e JSON usam a mesma fonte, sem informação extra oculta para persuadir crawlers. Microdata Person/VisualArtwork no HTML descreve o conteúdo visível; arquivo JSON separado contém a projeção estruturada, sem preço/Offer.
Cada idioma tem canonical próprio, hreflang recíproco en/pt-BR e x-default inglês. EN/PT são links reais. Não existe redirecionamento por país/Accept-Language, tradução por API ou fallback silencioso em chaves faltantes.

## llms.txt
Índice em Markdown, com resumo da artista, contexto, links para release e projetos em ambos idiomas. `llms-full.txt` consolida a mesma informação textual. HTML declara `rel="describedby"` para llms e `rel="alternate" type="text/markdown"` para sua contraparte. A proposta consultada admite localização em subpasta. Adoção por crawlers varia; isso não garante seleção, recomendação ou indexação.

## robots.txt e treinamento
Preview: política conservadora que não solicita indexação, meta noindex; site continua privado e sem deploy. `robots.txt` não é barreira de segurança nem mecanismo garantido de desindexação.
Release candidato: permite OAI-SearchBot e crawlers gerais no escopo do portfólio; GPTBot tem bloqueio separado no mesmo escopo como escolha conservadora para arte. Busca e treinamento não são equivalentes. Outros provedores têm regras próprias; o curinga não bloqueia todos os treinamentos. Bots acionados pelo usuário, como ChatGPT-User, podem ter comportamento diferente. Nenhum arquivo impede downloads ou cria proteção autoral universal.
A regra só é efetiva na raiz da origem. Em Pages por projeto, instalar/revisar no site de usuário ou usar domínio próprio; nunca marcar `robotsRootVerified` sem evidência HTTP. Ver docs/04.

## Paridade e revisão
UI localizada em `site/content/locales/en.json` e `pt-BR.json`. Bio/role/intro localizados em artist.json. Título/técnica/alt/transcrição precisam dos dois idiomas. O validador rejeita chaves divergentes, valor ausente ou tipo incorreto. A tradução inglesa foi preparada, mas `editorialReview.en` permanece false; release original português permanece aprovado.

## O que NÃO foi feito
Não há integração Gumroad, declaração de compra/venda, envio a diretórios, submissão a motores, chamada a provedor de IA, promessa de treinamento bloqueado universalmente, nem ativação do Pages. Esta fatia prepara os documentos e a arquitetura para uma publicação futura verificável.
